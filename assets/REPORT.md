# Vibe Studio 리포트 html 공통 규칙

각 스킬은 md 산출물을 저장한 뒤, 같은 내용을 사람이 보기 좋은 html로도 만든다. md는 에이전트가 읽는 원본이고, html은 사람이 보는 화면이다. 이 문서는 6개 스킬이 공통으로 따르는 규칙이다.

- **템플릿:** 이 파일과 같은 폴더의 `report-template.html`
- **문서별 구성:** 이 파일과 같은 폴더의 `views/{md 파일 이름}` (예: `views/PRODUCT.md`). 어떤 md 내용을 어떤 부품으로 보여줄지가 들어 있다.
- **결과물 위치:** md와 같은 `docs/` 폴더, 같은 이름에 확장자만 `.html`

## 0. 핵심 원칙 — html은 md 파일만 보고 만든다

html은 **저장된 md 파일을 다시 읽어서, 그 내용만으로** 채운다. 대화에서 들은 내용, 머릿속에 남은 맥락은 쓰지 않는다.

- 그래서 html은 언제 누가 다시 만들어도 같은 결과가 나온다. 앞 단계 대화를 모르는 다른 스킬이 html을 다시 그려도 마찬가지다.
- 사용자가 md를 직접 고쳐도 다음 생성 때 그대로 반영된다.
- html에 보여주고 싶은 내용이 있으면 **먼저 md에 적는다.** md에 없으면 html에도 없다.

## 순서

1. md를 파일로 저장한다.
2. 저장한 md 파일을 **다시 읽는다.**
3. `report-template.html`과 `views/{md 파일 이름}`을 읽는다.
4. 아래 규칙과 views의 구성대로 html을 만든다.
5. html을 **새로 만들었거나 서비스 이름이 바뀐 경우에만** 다른 html의 사이드바를 갱신한다(3번 규칙). 이미 있던 html을 다시 만든 것뿐이면 다른 파일은 건드리지 않는다.

## 1. 언제 만드나

- md를 **저장하거나 고칠 때마다** 그 md의 html을 다시 만든다. md만 고치고 html을 그대로 두지 않는다.
- 다른 단계의 md를 고친 경우(예: benchmark-research가 PRODUCT.md의 포지셔닝을 채움)에도, 그 md의 html이 이미 있으면 다시 만든다.
- html 생성 여부를 사용자에게 묻지 않는다. md와 함께 만드는 게 기본 동작이다.

## 2. 템플릿 사용법

`report-template.html`을 읽고 아래만 바꾼다. 나머지는 **한 글자도 바꾸지 않고 그대로 복사**한다.

| 바꾸는 곳 | 내용 |
|---|---|
| `<title>` | `{서비스 이름} — {문서 이름}` |
| `<aside class="sidebar">` 안 | 아래 3번 사이드바 규칙대로 |
| `<main>` 안 | `views/{md 파일 이름}`에 적힌 구성대로 |

- 맨 위 주석 블록(템플릿 설명)은 결과물에서 지운다.
- `<head>`의 폰트 링크, `<style>` 전체, 맨 아래 `<script>`는 그대로 둔다.
- **템플릿에 없는 스타일을 새로 만들지 않는다.** `style=""` 속성이나 새 class를 즉석에서 추가하지 않고, 템플릿 주석에 적힌 부품만 조합한다. 6개 화면이 같은 톤을 유지하기 위한 규칙이다. 필요한 부품이 없으면 가장 가까운 부품으로 표현하고, 보고할 때 "이런 부품이 있으면 좋겠다"고 한 줄 남긴다.
- md 내용을 html에 넣을 때 `<`, `>`, `&`는 `&lt;`, `&gt;`, `&amp;`로 바꾼다.
- 문장을 짧게 줄이는 건 되지만(views에 그렇게 적힌 곳), md에 없는 사실을 보태지 않는다. 비어 있는 섹션은 빈 상태로 보여준다.

## 3. 사이드바 규칙

사이드바는 6개 문서를 **항상 이 순서와 이름으로** 보여준다.

| # | 표시 이름 | 파일 |
|:-:|---|---|
| 1 | Product | `PRODUCT.html` |
| 2 | Benchmark | `benchmark.html` |
| 3 | User Flow | `userflow.html` |
| 4 | Voice | `VOICE.html` |
| 5 | Design | `DESIGN.html` |
| 6 | PRD | `PRD.html` |

- **지금 만드는 문서:** `<li class="is-current">`. 링크 아래에 `<ul class="toc">`로 이 문서의 섹션 목차를 단다. 목차 링크의 `href="#id"`는 `<main>` 안 `section`의 `id`와 맞춘다.
- **`docs/`에 html이 이미 있는 문서:** 클래스 없는 `<li>`로 링크만.
- **html이 아직 없는 문서:** `<li class="is-pending">`. ("준비 중"은 CSS가 자동으로 붙인다.)
- **브랜드 영역(`.brand`):** 서비스 이름. `docs/VOICE.md`에 확정 이름이 있으면 그것을, 없으면 `docs/PRODUCT.md`의 가칭을 쓴다. 아래 `<small>`은 `Vibe Studio` 그대로.

**다른 html의 사이드바도 갱신한다.** html을 새로 만들었거나 서비스 이름이 바뀌었으면, `docs/`에 이미 있는 다른 html들의 사이드바에서 아래 두 가지만 고친다. 각 파일의 `is-current`와 목차, `<main>`은 건드리지 않는다.
- 방금 만든 문서의 `<li>`에서 `is-pending`을 뗀다.
- `.brand`의 서비스 이름을 맞춘다. (`<title>`의 서비스 이름도 함께)

## 4. 공통 부품 쓰는 법

- **표지(`.cover`)는 모든 문서에 하나.** `.eyebrow`에 문서 표시 이름, `h1`에 서비스 이름, `.lead`에 그 문서의 한 줄 요약, `.meta`의 `.tag`로 상태·날짜 같은 짧은 정보.
- **섹션은 `section.section`에 `id`를 단다.** `.section-label`은 짧은 영어 라벨, `h2`는 한국어 제목.
- **푸터:** `Vibe Studio · 원본: docs/{md 파일 이름}`

## 5. 보고

html을 만든 뒤 사용자에게 보고할 때 html 경로를 같이 알려준다. 예: "브라우저로 `docs/PRODUCT.html`을 열면 한눈에 볼 수 있어요." 다른 html의 사이드바를 갱신했으면 그것도 한 줄로 알린다.
