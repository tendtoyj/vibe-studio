# Vibe Studio 리포트 html 공통 규칙

각 스킬은 md 산출물을 저장한 뒤, 같은 내용을 사람이 보기 좋은 html로도 만든다. md는 에이전트가 읽는 원본이고, html은 사람이 보는 화면이다. 이 문서는 5개 스킬이 공통으로 따르는 규칙이다.

- **템플릿:** 이 파일과 같은 폴더의 `report-template.html`
- **문서별 구성:** 이 파일과 같은 폴더의 `views/{md 파일 이름}` (예: `views/PRODUCT.md`). 어떤 md 내용을 어떤 부품으로 보여줄지가 들어 있다.
- **결과물 위치:** md와 같은 `docs/` 폴더, 같은 이름에 확장자만 `.html`

## 0. 핵심 원칙 — html은 md 파일만 보고 만든다

html은 **저장된 md 파일을 다시 읽어서, 그 내용만으로** 채운다. 대화에서 들은 내용, 머릿속에 남은 맥락은 쓰지 않는다.

기본은 같은 이름의 md 하나다(`PRODUCT.md` → `PRODUCT.html`). 다른 md의 요약을 함께 보여줘야 하는 문서는 `views/`에 **어떤 md를 더 읽는지** 적혀 있고, 그 파일들도 같은 원칙으로 읽는다(예: PRODUCT.html은 VOICE.md·DESIGN.md의 요약 카드를 함께 보여준다).

- 그래서 html은 언제 누가 다시 만들어도 같은 결과가 나온다. 앞 단계 대화를 모르는 다른 스킬이 html을 다시 그려도 마찬가지다.
- 사용자가 md를 직접 고쳐도 다음 생성 때 그대로 반영된다.
- html에 보여주고 싶은 내용이 있으면 **먼저 md에 적는다.** md에 없으면 html에도 없다.

## 순서

1. md를 파일로 저장한다.
2. 저장한 md 파일을 **다시 읽는다.** views에 함께 읽을 md가 적혀 있으면 그것도 읽는다.
3. `report-template.html`과 `views/{md 파일 이름}`을 읽는다.
4. 아래 규칙과 views의 구성대로 html을 만든다.
5. html을 **새로 만들었거나 서비스 이름이 바뀐 경우에만** 다른 html의 사이드바를 갱신한다(3번 규칙). 이미 있던 html을 다시 만든 것뿐이면 다른 파일은 건드리지 않는다.

## 1. 언제 만드나

- md를 **저장하거나 고칠 때마다** 그 md의 html을 다시 만든다. md만 고치고 html을 그대로 두지 않는다.
- 다른 단계의 md를 고친 경우(예: benchmark-research가 PRODUCT.md의 포지셔닝을 채움)에도, 그 md의 html이 이미 있으면 다시 만든다.
- 어떤 md가 바뀌었을 때, 그 md를 **함께 읽는** 다른 html이 있으면 그것도 다시 만든다(예: VOICE.md나 DESIGN.md가 바뀌면 PRODUCT.html도).
- html 생성 여부를 사용자에게 묻지 않는다. md와 함께 만드는 게 기본 동작이다.

## 2. 템플릿 사용법

`report-template.html`을 읽고 아래를 바꾼다. 템플릿의 기본 스타일은 그대로 복사해서 쓴다.

| 바꾸는 곳 | 내용 |
|---|---|
| `<title>` | `{서비스 이름} — {문서 이름}` |
| `<aside class="sidebar">` 안 | 아래 3번 사이드바 규칙대로 |
| `<main>` 안 | `views/{md 파일 이름}`에 적힌 구성대로 (views가 넓은 페이지를 쓰라고 하면 `<main class="is-wide">`) |

- 맨 위 주석 블록(템플릿 설명)은 결과물에서 지운다.
- `<head>`의 폰트 링크, `<style>` 블록, 맨 아래 `<script>`는 그대로 둔다. 기본 스타일을 고쳐 쓰지 않는 이유는 5개 화면의 톤을 같게 유지하기 위해서다.
- **먼저 템플릿 주석에 적힌 부품으로 표현한다.** 대부분은 기존 부품 조합으로 충분하다.
- **맞는 부품이 없으면 새로 만들어도 된다.** 내용을 억지로 기존 부품에 끼워 맞추느라 읽기 어려워지는 것보다 낫다. 다만 기존 디자인에 맞춘다:
  - 템플릿 `<style>` 바로 아래에 `<style>` 블록을 하나 더 두고 거기에 쓴다(기존 블록은 고치지 않는다).
  - 색·둥글기·폭은 `:root`의 변수(`--ink`, `--line`, `--surface`, `--accent`, `--radius` 등)만 쓴다. 새 색을 직접 지정하지 않는다.
  - 글자 크기·굵기·간격은 기존 부품과 비슷한 값으로 맞춘다(본문 14~15px, 보조 12~13px 등).
  - 휴대폰 화면(860px 이하)에서도 깨지지 않게 한다.
  - 보고할 때 새로 만든 부품을 한 줄로 알린다. 여러 문서에서 쓸 만하면 템플릿에 정식으로 넣을지 검토할 수 있게.
- **예외 — 디자인 견본 부품 안에서는 DESIGN.md의 실제 값을 쓴다.** 색 견본(`.swatch`), 글꼴 예시(`.type-sample`), 간격·모서리·그림자 상자(`.token-box`), 표 안 색 점(`.dot`), 컴포넌트 미리보기(`.ds-preview`)는 우리 서비스의 디자인을 보여주는 게 목적이므로, DESIGN.md에 적힌 색·글꼴·수치를 `style=""`로 넣는다. 그 바깥(사이드바, 제목, 설명 글)은 다른 문서와 같은 템플릿 색을 유지한다.
- 브랜드 글꼴이 템플릿 기본 글꼴(Pretendard)이 아니면, 그 글꼴을 쓰는 html에만 웹폰트 `<link>`를 `<head>`에 하나 더 넣는다(Google Fonts 또는 jsdelivr). 불러올 수 없는 글꼴이면 넣지 않고, 시스템 글꼴로 보인다는 점을 보고에 적는다.
- md 내용을 html에 넣을 때 `<`, `>`, `&`는 `&lt;`, `&gt;`, `&amp;`로 바꾼다.
- 문장을 짧게 줄이는 건 되지만(views에 그렇게 적힌 곳), md에 없는 사실을 보태지 않는다. 비어 있는 섹션은 빈 상태로 보여준다.

## 3. 사이드바 규칙

사이드바는 5개 문서를 **항상 이 순서와 이름으로** 보여준다.

| # | 표시 이름 | 파일 |
|:-:|---|---|
| 1 | Product | `PRODUCT.html` |
| 2 | Benchmark | `benchmark.html` |
| 3 | Voice | `VOICE.html` |
| 4 | Design | `DESIGN.html` |
| 5 | Flows | `FLOWS.html` |

- **지금 만드는 문서:** `<li class="is-current">`. 링크 아래에 `<ul class="toc">`로 이 문서의 섹션 목차를 단다. 목차 링크의 `href="#id"`는 `<main>` 안 `section`의 `id`와 맞춘다.
- **`docs/`에 html이 이미 있는 문서:** 클래스 없는 `<li>`로 링크만.
- **html이 아직 없는 문서:** `<li class="is-pending">`. ("준비 중"은 CSS가 자동으로 붙인다.)
- **브랜드 영역(`.brand`):** 서비스 이름. 항상 `docs/PRODUCT.md` 제목의 이름을 쓴다(brand-voice가 이름을 확정하면 PRODUCT.md 제목도 바꾸므로 이게 기준이다). 아래 `<small>`은 `Vibe Studio` 그대로.

**다른 html의 사이드바도 갱신한다.** html을 새로 만들었거나 서비스 이름이 바뀌었으면, `docs/`에 이미 있는 다른 html들을 아래처럼 고친다. 각 파일의 `<main>`은 건드리지 않는다.
- **문서 목록(`ul.nav`)은 위 표와 규칙대로 통째로 다시 쓴다.** 그 파일 자신의 `is-current`와 목차(`ul.toc`)만 그대로 옮겨 넣는다. 일부만 고치지 않는 이유: 예전 버전으로 만든 html은 목록 순서나 문서 구성이 지금과 다를 수 있어서다.
- `.brand`와 `<title>`의 서비스 이름을 맞춘다.
- `<style>` 블록을 지금 템플릿의 것으로 바꾼다(추가 `<style>` 블록이 있으면 그대로 둔다). 템플릿이 업데이트돼도 예전 html이 새 부품을 그릴 수 있게 하기 위해서다.

## 4. 공통 부품 쓰는 법

- **표지(`.cover`)는 모든 문서에 하나.** `.eyebrow`에 문서 표시 이름, `h1`에 서비스 이름, `.lead`에 그 문서의 한 줄 요약, `.meta`의 `.tag`로 상태·날짜 같은 짧은 정보.
- **섹션은 `section.section`에 `id`를 단다.** `.section-label`은 짧은 영어 라벨, `h2`는 한국어 제목.
- **푸터:** `Vibe Studio · 원본: docs/{md 파일 이름}`

## 5. 보고

html을 만든 뒤 사용자에게 보고할 때 html 경로를 같이 알려준다. 예: "브라우저로 `docs/PRODUCT.html`을 열면 한눈에 볼 수 있어요." 다른 html의 사이드바를 갱신했으면 그것도 한 줄로 알린다.
